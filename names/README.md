# names/

Function names for the Trilogy binaries, one CSV per binary and source: `<binary>.<source>.csv`.

| Column | Meaning |
|---|---|
| `address` | Function entry VA (hex) |
| `name` | Name without suffix |
| `confidence` | `certain` = applied as is; anything else = applied with a `_guess` suffix |
| `source` | `manual`, `fid`, `eqclassic`, `mac`, `strings`, `beta`, `takp` |
| `note` | Our one-line reason for the name. A note starting `library:` marks third-party/CRT code |
| `from_address` | Optional: the function in the build the name came from (TAKP `eqgame.exe` for `mac`/`takp`, the 1999 beta `eqgame.exe` for `beta`) |
| `file` | Optional: original source file, from the Mac client's debug map |

Apply to the Ghidra project with `tools\ghidra\scripts\apply_names.py trilogy`. Imported names never
replace a name someone set by hand in Ghidra. Where several lists name one address, the order is
`manual`, `fid`, `eqclassic`, `mac`, `strings`, `beta`, `takp`; the losing names stay visible in the
function's plate comment. The winning row's `library:` note also puts the LIBRARY tag on the function. A
name the script applied earlier whose row has since disappeared from every list goes back to `FUN_`.

`eqgame.manual.csv` holds names checked by hand; it beats every generated list.

`eqgame.mac.csv` and `eqgame.takp.csv` are generated by `tools\ghidra\scripts\name_chain.py trilogy`
(don't edit them; put corrections in `eqgame.manual.csv`). Each row is a TAKP function matched to a
Trilogy function, carrying the TAKP function's name:
- `mac`: the name is a symbol of the Intel Mac client, so it is an original name.
- `takp`: the name occurs only in the community TAKP function list. These are descriptive inventions,
  always `low`.
- Confidence `high` / `medium` / `low` is the weaker of "TAKP function has this name" and "this Trilogy
  function is that TAKP function". The note gives the evidence (BinDiff similarity/confidence, unique
  strings, call position).
- Post-Luclin UI names are capped at `low` and say so in the note.

`eqgame.beta.csv` is generated by `tools\ghidra\scripts\name_beta.py` (don't edit it either). The names
come from the January 1999 beta client's own debug strings (each names the function it
is in), so they are the developers' names, bare (no class). A row
exists when Trilogy still references the naming string itself, or when the beta function it names is
matched to this Trilogy function (strings, constants, BinDiff, call position); `from_address` is the beta
function. Confidence is the weaker of "the beta function has this name" and "this Trilogy function is that
beta function"; a naming string Trilogy references itself counts as the name on its own.
- Debug strings can name the wrong function: messages were copied between functions (`BaseAttr` says
  "...", missile code says "in DoCamAi()"). Where the chain has the name on another function
  at `medium` or better, the row is capped at `low` and its note starts with `CHAIN PUTS`.
- `beta` ranks after `mac` (where they agree, the Mac symbol also carries the class) and before `takp`
  (descriptive inventions).

`eqgame.strings.csv` is generated by `name_beta.py` too: Trilogy functions named by their own debug
strings (the ones the beta doesn't have; same patterns and rules as the beta names, one function per name).
62 of them are libxml2 2.3.6 (version from its `xmlParserVersion` string `"20306"`), noted
`library: libxml2 2.3.6`; inside the libxml block only `xml*`/`html*` names count (its messages also name
grammar productions like `EntityValue`), and valid.c's `xmlAddIDDecl:`/`xmlAddRefDecl:` messages belong to
`xmlAddID`/`xmlAddRef`. `strings` ranks after `mac` and before `beta`.

`eqgame.fid.csv` is generated by `tools\ghidra\scripts\fid_names.py trilogy`: VC6 CRT helpers whose exact
Function ID hash is in `vc6_x86.fidb` but which are too short for FID's score threshold (`__EH_prolog`,
`__cfltcvt_init`, ...). All are `library:` rows; `certain` from 10 instructions up, `high` below.

The names in `eqgame.eqclassic.csv` come from comments in the EQClassic source that cite a client address
(`tools\ghidra\scripts\extract_eqclassic_notes.py` lists them; that list quotes EQClassic and is not
published), picked by hand together with the strings the function references.

`eqgfx_dx7.mac.csv` and `eqgame.mac.direct.csv` are generated by `tools\ghidra\scripts\name_mac_direct.py gfx|game`
(don't edit them). Mac symbols matched straight onto the Trilogy binary, without TAKP in between: seeds are
symbols both sides already carry (DX7 exports; names already in `eqgame.mac.csv`/`manual`), then unique strings,
constants, weak BinDiff and a neighbourhood vote (callers+callees that are the same matched functions, at least 2
and Jaccard >= 0.6). Only addresses not already named by the chain are listed. Held-out check (25% of the seeds
hidden and re-found): DX7 30/32 right, eqgame 98/104 right. `note` carries the C++ signature when the mangled
symbol was decodable.
